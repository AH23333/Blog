# 从Manus到ChatGPT Agent：底层技术架构有何不同？

> **播客：** 硅谷101 | **主播：** 泓君Jane | **日期：** 2025年7月
> **嘉宾：** Agent技术专家
> **时长：** 39分钟

## 节目概要

Manus的横空出世让AI Agent成为2025年最受关注的技术话题之一。它号称能够自主执行复杂任务——从编写代码到浏览网页、从数据分析到生成报告，全程无需人类干预。但Manus与ChatGPT Agent、Claude Computer Use、Adept等主流Agent框架在底层技术上到底有何不同？它们的架构设计各有什么优劣？

本期节目邀请Agent技术专家，深入拆解不同Agent框架的底层技术架构。从任务规划、工具调用、记忆机制到多步推理，逐一对比Manus、ChatGPT Agent、Claude Agent等主流框架的核心设计差异。节目还探讨了"自主执行"与"辅助执行"两种范式之间的权衡，以及代码执行和浏览器自动化在Agent中的关键作用。

## 核心观点

### 1. Manus架构深度解析

- Manus的核心架构分为三个关键层次：
  1. **任务规划层（Planning Layer）**：接收用户指令，将其分解为可执行的子任务序列
  2. **执行引擎层（Execution Engine）**：在沙箱环境中执行代码、调用工具、浏览网页
  3. **记忆与状态层（Memory & State）**：维护任务执行的上下文和中间状态
- Manus的突出特点：**端到端自主执行**——用户只需给出最终目标，Manus自主完成从规划到执行的全过程
- 技术实现上，Manus在底层使用了**代码作为中间表示**：将复杂任务转化为Python代码，在隔离的沙箱环境中执行
- 沙箱环境提供了完整的Linux环境，可以安装依赖、运行脚本、操作文件系统
- 浏览器自动化方面，Manus可以控制浏览器完成网页操作（搜索、点击、填表、数据提取），类似于RPA（机器人流程自动化）但更加智能和灵活

### 2. ChatGPT Agent架构对比

- ChatGPT Agent（包括ChatGPT Tasks、Operator等）采用**模型原生集成**的架构
- 核心特点：**工具调用（Function Calling）内置于模型推理过程中**，而非外部框架
- 架构层次：
  - 模型层直接输出"工具调用"指令（JSON格式的函数名+参数）
  - 运行时环境执行工具调用并将结果返回模型
  - 模型根据结果决定下一步行动
- ChatGPT Agent的优势：**与模型能力深度耦合**，工具调用的准确性随着模型能力提升而自然提升
- ChatGPT Agent的局限：**自主性相对受限**——目前更多是"辅助执行"模式，需要用户在关键节点确认和介入
- OpenAI的Operator更进一步，直接控制浏览器（类似Manus的浏览器自动化），但目前仍处于早期阶段

### 3. 任务规划机制对比

| 维度 | Manus | ChatGPT Agent | Claude Agent |
|------|-------|--------------|-------------|
| **规划方式** | 显式分层规划（Plan → Execute） | 隐式链式推理（Chain-of-Thought） | 结构化任务分解 |
| **规划粒度** | 粗到细的分层分解 | 逐步推理，动态调整 | 中等粒度，结构化输出 |
| **可解释性** | 高——用户可以看到完整计划 | 中——通过思维链可见推断过程 | 高——结构化输出 |
| **容错能力** | 计划失败时重新规划 | 逐步推理，天然容错 | 任务失败时回溯 |

- Manus采用**显式规划**：先制定完整计划，再逐步执行。优点是用户可以看到全貌，缺点的计划一旦出错需要重新规划
- ChatGPT Agent采用**隐式推理**：通过Chain-of-Thought在每一步推理中动态决定下一步，更灵活但缺乏全局视角
- Claude Agent采用**结构化任务分解**：使用XML/JSON等结构化格式输出任务计划，兼顾可读性和可执行性

### 4. 工具调用机制对比

- **Function Calling（函数调用）**：ChatGPT Agent的核心工具调用方式
  - 模型输出指定格式的函数名和参数
  - 优势：标准化、与模型推理深度集成
  - 局限：需要预先定义所有可用工具，灵活性受限

- **代码执行（Code Execution）**：Manus的核心工具调用方式
  - 将任务转化为代码，在沙箱中执行
  - 优势：**图灵完备**——理论上可以做任何事情，可以动态安装和使用任何Python库
  - 局限：代码执行的安全风险、执行效率、错误处理复杂度

- **浏览器自动化**：两者都支持，但实现方式不同
  - Manus：通过Playwright等工具控制浏览器，执行复杂网页操作
  - ChatGPT Operator：通过计算机视觉理解屏幕内容，模拟用户操作
  - 关键差异：**Manus偏重结构化操作（DOM级），Operator偏重视觉理解（像素级）**

- **文件系统操作**：Agent能否读写文件、管理目录、处理多种文件格式
  - Manus提供了完整的Linux文件系统访问
  - ChatGPT Agent通过Code Interpreter提供受限的文件系统访问

### 5. 记忆机制对比

- **短期记忆（上下文窗口）**：
  - 所有Agent都依赖模型的上下文窗口作为短期记忆
  - 挑战：长任务执行中，上下文窗口可能被填满，导致"遗忘"
  - 解决方案：滑动窗口、摘要压缩、分层记忆

- **长期记忆（持久化存储）**：
  - Manus：通过文件系统和数据库维护任务状态，跨会话持久化
  - ChatGPT Agent：通过"Memory"功能跨会话记忆用户偏好，但任务级别的记忆有限
  - Claude Agent：通过Project Knowledge维护项目级别的长期记忆

- **工作记忆（Working Memory）**：
  - 任务执行过程中的中间状态管理
  - Manus的沙箱环境天然提供了工作记忆空间
  - ChatGPT Agent依赖上下文窗口+外部存储

### 6. 多步推理能力对比

- 多步推理是Agent执行复杂任务的核心能力，涉及：**保持上下文、追踪中间结果、处理分支逻辑、从错误中恢复**
- Manus的多步推理强项：代码执行天然支持条件分支、循环和错误处理，适合确定性强的任务
- ChatGPT Agent的多步推理强项：模型本身的推理能力，适合需要灵活判断和模糊决策的任务
- 关键差异：**Manus更像是"程序化"推理，ChatGPT Agent更像是"启发式"推理**
- 一个实际案例：生成一份竞品分析报告
  - Manus：写代码 → 搜索 → 抓取数据 → 分析 → 生成图表 → 撰写报告
  - ChatGPT Agent：逐步推理 → 调用搜索工具 → 读取网页 → 分析 → 调用代码解释器生成图表 → 撰写报告

### 7. 自主执行 vs 辅助执行：两种范式的权衡

| 维度 | 自主执行（Manus） | 辅助执行（ChatGPT Agent） |
|------|------------------|-------------------------|
| **用户参与度** | 低——设定目标后放手 | 高——关键节点需要确认 |
| **执行速度** | 快——无等待时间 | 慢——需要用户反馈 |
| **可靠性** | 风险较高——出错可能连锁反应 | 风险较低——人工把关 |
| **适用场景** | 明确、可验证的任务 | 探索性、需要判断的任务 |
| **用户体验** | "魔法感"强，但失控感也强 | 协同感强，可控 |

- 自主执行的理想场景：确定性任务（如数据清洗、报告生成、定时任务）
- 辅助执行的理想场景：需要人类判断的任务（如创意写作、战略分析、敏感决策）
- 未来趋势：**混合模式**——Agent在低风险环节自主执行，在高风险环节请求人类介入
- 投资人视角：**自主执行是Agent的终极形态，但辅助执行是当前阶段更务实的选择**

### 8. Agent框架选型的技术考量

- 选择Agent框架的关键考量：
  - **任务类型**：确定性任务 → 代码执行型Agent；探索性任务 → 推理型Agent
  - **安全要求**：高安全要求 → 沙箱隔离 + 权限管控
  - **集成需求**：企业环境 → 与现有系统的API集成能力
  - **可扩展性**：多Agent协作 → 标准化通信协议
- 当前Agent框架的共性挑战：
  - **可靠性**：多步任务的失败率仍然较高
  - **成本**：长任务的Token消耗巨大
  - **安全**：Agent自主执行代码和浏览网页的安全风险
  - **评估**：缺乏标准化的Agent能力评估基准

## 关键洞察

> "Manus和ChatGPT Agent代表了两种不同的Agent哲学：Manus相信'给Agent一个沙箱，它能做任何事'，ChatGPT Agent相信'Agent应该是人类能力的延伸，而非替代'。"

> "代码作为Agent的中间表示，是一个被低估的技术选择。代码是图灵完备的、可验证的、可复用的——这些特性让它成为Agent执行复杂任务的理想载体。"

> "评测Agent好坏的标准不是'它能做什么'，而是'它做错了什么'。一个Agent在100个任务中成功了99个，但如果那1个失败的后果是灾难性的，那这个Agent就不能被信任。"

> "自主执行和辅助执行之间没有对错之分，只有场景之分。好的Agent不是越自主越好，而是越适配用户需求越好。"
