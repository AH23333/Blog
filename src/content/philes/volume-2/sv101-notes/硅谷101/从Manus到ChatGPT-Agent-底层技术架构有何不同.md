# 从 Manus 到 ChatGPT Agent：底层技术架构有何不同？

> **播客：** 硅谷 101 | **主播：** 泓君 Jane | **日期：** 2025 年 7 月
> **嘉宾：** Agent 技术专家
> **时长：** 39 分钟

---

## 节目概要

Manus 的横空出世让 AI Agent 成为 2025 年最受关注的技术话题之一。它号称能够自主执行复杂任务——从编写代码到浏览网页、从数据分析到生成报告，全程无需人类干预。但 Manus 与 ChatGPT Agent、Claude Computer Use、Adept 等主流 Agent 框架在底层技术上到底有何不同？它们的架构设计各有什么优劣？

本期节目邀请 Agent 技术专家，深入拆解不同 Agent 框架的底层技术架构。从任务规划、工具调用、记忆机制到多步推理，逐一对比 Manus、ChatGPT Agent、Claude Agent 等主流框架的核心设计差异。节目还探讨了"自主执行"与"辅助执行"两种范式之间的权衡，以及代码执行和浏览器自动化在 Agent 中的关键作用。

## 核心观点

### 1. Manus 架构深度解析

- Manus 的核心架构分为三个关键层次：
  1. **任务规划层（Planning Layer）**：接收用户指令，将其分解为可执行的子任务序列
  2. **执行引擎层（Execution Engine）**：在沙箱环境中执行代码、调用工具、浏览网页
  3. **记忆与状态层（Memory & State）**：维护任务执行的上下文和中间状态
- Manus 的突出特点：**端到端自主执行**——用户只需给出最终目标，Manus 自主完成从规划到执行的全过程
- 技术实现上，Manus 在底层使用了**代码作为中间表示**：将复杂任务转化为 Python 代码，在隔离的沙箱环境中执行
- 沙箱环境提供了完整的 Linux 环境，可以安装依赖、运行脚本、操作文件系统
- 浏览器自动化方面，Manus 可以控制浏览器完成网页操作（搜索、点击、填表、数据提取），类似于 RPA（机器人流程自动化）但更加智能和灵活

### 2. ChatGPT Agent 架构对比

- ChatGPT Agent（包括 ChatGPT Tasks、Operator 等）采用**模型原生集成**的架构
- 核心特点：**工具调用（Function Calling）内置于模型推理过程中**，而非外部框架
- 架构层次：
  - 模型层直接输出"工具调用"指令（JSON 格式的函数名+参数）
  - 运行时环境执行工具调用并将结果返回模型
  - 模型根据结果决定下一步行动
- ChatGPT Agent 的优势：**与模型能力深度耦合**，工具调用的准确性随着模型能力提升而自然提升
- ChatGPT Agent 的局限：**自主性相对受限**——目前更多是"辅助执行"模式，需要用户在关键节点确认和介入
- OpenAI 的 Operator 更进一步，直接控制浏览器（类似 Manus 的浏览器自动化），但目前仍处于早期阶段

### 3. 任务规划机制对比

| 维度         | Manus                          | ChatGPT Agent                    | Claude Agent         |
| ------------ | ------------------------------ | -------------------------------- | -------------------- |
| **规划方式** | 显式分层规划（Plan → Execute） | 隐式链式推理（Chain-of-Thought） | 结构化任务分解       |
| **规划粒度** | 粗到细的分层分解               | 逐步推理，动态调整               | 中等粒度，结构化输出 |
| **可解释性** | 高——用户可以看到完整计划       | 中——通过思维链可见推断过程       | 高——结构化输出       |
| **容错能力** | 计划失败时重新规划             | 逐步推理，天然容错               | 任务失败时回溯       |

- Manus 采用**显式规划**：先制定完整计划，再逐步执行。优点是用户可以看到全貌，缺点的计划一旦出错需要重新规划
- ChatGPT Agent 采用**隐式推理**：通过 Chain-of-Thought 在每一步推理中动态决定下一步，更灵活但缺乏全局视角
- Claude Agent 采用**结构化任务分解**：使用 XML/JSON 等结构化格式输出任务计划，兼顾可读性和可执行性

### 4. 工具调用机制对比

- **Function Calling（函数调用）**：ChatGPT Agent 的核心工具调用方式

  - 模型输出指定格式的函数名和参数
  - 优势：标准化、与模型推理深度集成
  - 局限：需要预先定义所有可用工具，灵活性受限

- **代码执行（Code Execution）**：Manus 的核心工具调用方式

  - 将任务转化为代码，在沙箱中执行
  - 优势：**图灵完备**——理论上可以做任何事情，可以动态安装和使用任何 Python 库
  - 局限：代码执行的安全风险、执行效率、错误处理复杂度

- **浏览器自动化**：两者都支持，但实现方式不同

  - Manus：通过 Playwright 等工具控制浏览器，执行复杂网页操作
  - ChatGPT Operator：通过计算机视觉理解屏幕内容，模拟用户操作
  - 关键差异：**Manus 偏重结构化操作（DOM 级），Operator 偏重视觉理解（像素级）**

- **文件系统操作**：Agent 能否读写文件、管理目录、处理多种文件格式
  - Manus 提供了完整的 Linux 文件系统访问
  - ChatGPT Agent 通过 Code Interpreter 提供受限的文件系统访问

### 5. 记忆机制对比

- **短期记忆（上下文窗口）**：

  - 所有 Agent 都依赖模型的上下文窗口作为短期记忆
  - 挑战：长任务执行中，上下文窗口可能被填满，导致"遗忘"
  - 解决方案：滑动窗口、摘要压缩、分层记忆

- **长期记忆（持久化存储）**：

  - Manus：通过文件系统和数据库维护任务状态，跨会话持久化
  - ChatGPT Agent：通过"Memory"功能跨会话记忆用户偏好，但任务级别的记忆有限
  - Claude Agent：通过 Project Knowledge 维护项目级别的长期记忆

- **工作记忆（Working Memory）**：
  - 任务执行过程中的中间状态管理
  - Manus 的沙箱环境天然提供了工作记忆空间
  - ChatGPT Agent 依赖上下文窗口+外部存储

### 6. 多步推理能力对比

- 多步推理是 Agent 执行复杂任务的核心能力，涉及：**保持上下文、追踪中间结果、处理分支逻辑、从错误中恢复**
- Manus 的多步推理强项：代码执行天然支持条件分支、循环和错误处理，适合确定性强的任务
- ChatGPT Agent 的多步推理强项：模型本身的推理能力，适合需要灵活判断和模糊决策的任务
- 关键差异：**Manus 更像是"程序化"推理，ChatGPT Agent 更像是"启发式"推理**
- 一个实际案例：生成一份竞品分析报告
  - Manus：写代码 → 搜索 → 抓取数据 → 分析 → 生成图表 → 撰写报告
  - ChatGPT Agent：逐步推理 → 调用搜索工具 → 读取网页 → 分析 → 调用代码解释器生成图表 → 撰写报告

### 7. 自主执行 vs 辅助执行：两种范式的权衡

| 维度           | 自主执行（Manus）          | 辅助执行（ChatGPT Agent） |
| -------------- | -------------------------- | ------------------------- |
| **用户参与度** | 低——设定目标后放手         | 高——关键节点需要确认      |
| **执行速度**   | 快——无等待时间             | 慢——需要用户反馈          |
| **可靠性**     | 风险较高——出错可能连锁反应 | 风险较低——人工把关        |
| **适用场景**   | 明确、可验证的任务         | 探索性、需要判断的任务    |
| **用户体验**   | "魔法感"强，但失控感也强   | 协同感强，可控            |

- 自主执行的理想场景：确定性任务（如数据清洗、报告生成、定时任务）
- 辅助执行的理想场景：需要人类判断的任务（如创意写作、战略分析、敏感决策）
- 未来趋势：**混合模式**——Agent 在低风险环节自主执行，在高风险环节请求人类介入
- 投资人视角：**自主执行是 Agent 的终极形态，但辅助执行是当前阶段更务实的选择**

### 8. Agent 框架选型的技术考量

- 选择 Agent 框架的关键考量：
  - **任务类型**：确定性任务 → 代码执行型 Agent；探索性任务 → 推理型 Agent
  - **安全要求**：高安全要求 → 沙箱隔离 + 权限管控
  - **集成需求**：企业环境 → 与现有系统的 API 集成能力
  - **可扩展性**：多 Agent 协作 → 标准化通信协议
- 当前 Agent 框架的共性挑战：
  - **可靠性**：多步任务的失败率仍然较高
  - **成本**：长任务的 Token 消耗巨大
  - **安全**：Agent 自主执行代码和浏览网页的安全风险
  - **评估**：缺乏标准化的 Agent 能力评估基准

## 关键洞察

> "Manus 和 ChatGPT Agent 代表了两种不同的 Agent 哲学：Manus 相信'给 Agent 一个沙箱，它能做任何事'，ChatGPT Agent 相信'Agent 应该是人类能力的延伸，而非替代'。"

> "代码作为 Agent 的中间表示，是一个被低估的技术选择。代码是图灵完备的、可验证的、可复用的——这些特性让它成为 Agent 执行复杂任务的理想载体。"

> "评测 Agent 好坏的标准不是'它能做什么'，而是'它做错了什么'。一个 Agent 在 100 个任务中成功了 99 个，但如果那 1 个失败的后果是灾难性的，那这个 Agent 就不能被信任。"

> "自主执行和辅助执行之间没有对错之分，只有场景之分。好的 Agent 不是越自主越好，而是越适配用户需求越好。"
